# Голос и телефония

Решение: звонки ведёт **ElevenLabs Agents**, а Plumo подключён к нему как **Custom LLM**. Speech-to-speech модель (OpenAI Realtime) не берём.

## Почему так

| | ElevenLabs Agents + Plumo как Custom LLM | OpenAI Realtime (speech-to-speech) |
| --- | --- | --- |
| Один мозг для чата и звонка | Да. Каждая реплика идёт через `AgentService`: память, база знаний, роутер, валидатор, handoff | Нет. Модель слышит и говорит сама, наше ядро становится тулом сбоку |
| «Не выдумывать цены» | Валидатор проверяет ответ **до** синтеза | Голос генерируется сразу, проверить цену до того, как её услышат, нельзя |
| Роутер small/big | Работает: дешёвая модель на типовых репликах | Одна дорогая модель на каждую реплику |
| Кыргызский | Scribe распознаёт кыргызский. Синтез на кыргызском есть у `eleven_v3`, `eleven_v3_conversational`, `eleven_v4`, `eleven_v4_turbo`; у `eleven_flash_v2_5` **нет** (`GET /v1/models`, 9 октября 2026) | Кыргызский официально не заявлен |
| SIP / номер | SIP-транк: Zadarma/Telnyx → ElevenLabs | SIP есть (`sip.api.openai.com`) |
| Перебивание, VAD, паузы | Из коробки | Из коробки |
| Задержка | Выше: STT → наш HTTP → LLM → TTS | Ниже всех |
| Цена | Платформа за минуту + наша LLM с роутером | Аудиотокены: $32 / 1M на вход, $64 / 1M на выход |
| Замена провайдера | Голос меняется, ядро нет | Переписывать логику под модель |

Главный аргумент — правило продукта: факты только из базы. В STS-модели между «модель решила» и «клиент услышал» нет места для валидатора. Второй аргумент — экономика роутера: STS убивает его целиком.

Риск: кыргызский синтез в реалтайме. Если тест (неделя 1–2, 50 записей, WER на смешанной речи до ~20%) не пройдёт, работаем по запасному плану из продуктового документа: голос на русском, кыргызский в голосовых сообщениях чатов. Ядро от этого не меняется.

## Как идёт звонок

```
Покупатель → номер бизнеса → переадресация → номер Zadarma/Telnyx
  → SIP-транк → ElevenLabs Agent (STT, паузы, перебивание)
     ├─ initiation webhook → Plumo: кто звонит → приветствие + «в прошлый раз вы спрашивали…»
     ├─ каждая реплика → Plumo /v1/chat/completions → AgentService (channel=voice) → SSE
     └─ после звонка → Plumo post-call webhook → voice_calls (длительность, стоимость)
  ← TTS ← ответ
```

Ответ уходит в ElevenLabs одним куском после валидатора. Токены не стримим нарочно: иначе непроверенная цена успеет прозвучать.

## Эндпоинты Plumo

| Путь | Кто зовёт | Авторизация |
| --- | --- | --- |
| `POST /api/v1/telephony/elevenlabs/v1/chat/completions` | Custom LLM, каждая реплика | `Authorization: Bearer $ELEVENLABS_LLM_TOKEN` |
| `POST /api/v1/telephony/elevenlabs/initiation` | Начало входящего звонка | тот же Bearer (или `X-Plumo-Token`) |
| `POST /api/v1/telephony/elevenlabs/post-call` | После звонка | HMAC `ElevenLabs-Signature`, секрет `$ELEVENLABS_WEBHOOK_SECRET` |

Код: `src/app/api/routes/telephony.py` (HTTP), `src/app/infrastructure/telephony/elevenlabs.py` (формат), `src/app/application/services/call_service.py` (логика). Звонки лежат в таблице `voice_calls` (миграция `002_voice_calls`), реплики — в обычных `messages` того же клиента.

## Настройка ElevenLabs

Пункты 1–4 делает скрипт. Он живёт вне ядра и обращается к API ElevenLabs только при запуске:

```powershell
# в backend/.env: ELEVENLABS_API_KEY=..., backend доступен снаружи по https
.venv\Scripts\python -m app.elevenlabs_setup --public-url https://<host> --dry-run   # показать конфиг
.venv\Scripts\python -m app.elevenlabs_setup --public-url https://<host>
```

Скрипт создаёт секрет Custom LLM, post-call webhook и агента. Id и секреты он записывает в `backend/.env`: `ELEVENLABS_LLM_TOKEN`, если его не было, `ELEVENLABS_WEBHOOK_SECRET`, `ELEVENLABS_AGENT_ID` и другие. При повторном запуске обновляется тот же агент. Если ngrok выдал новый адрес, запустите скрипт ещё раз. Если поменяли `ELEVENLABS_LLM_TOKEN`, очистите `ELEVENLABS_LLM_SECRET_ID`, и скрипт создаст новый секрет. После запуска перезапустите backend. Голос (пункт 5) и номер (пункт 6) настраиваются в панели или через `ELEVENLABS_VOICE_ID` / `ELEVENLABS_TTS_MODEL`.

Вручную, если без скрипта:

1. Agent → **LLM: Custom LLM**. Server URL: `https://<host>/api/v1/telephony/elevenlabs/v1`, Model ID: `plumo`, API key: значение `ELEVENLABS_LLM_TOKEN`.
2. **System prompt** агента — только маркеры, логика живёт в Plumo:
   `plumo_caller={{system__caller_id}} plumo_call={{system__conversation_id}} plumo_called={{system__called_number}}`
   `plumo_called` выбирает бизнес: номер должен быть в `contacts.voice_numbers` этого бизнеса.
3. **Security → Overrides**: разрешить first message и language. Включить conversation initiation webhook на `/initiation` с заголовком `Authorization: Bearer <token>`.
4. **Post-call webhook** на `/post-call`, секрет положить в `ELEVENLABS_WEBHOOK_SECRET`.
5. Голос и поведение — таблица в разделе «Чтобы звучало как человек».
6. **Phone numbers → SIP trunk**: импортировать номер, в ElevenLabs ACL или digest-авторизация. Звук 48 кГц — транк должен уметь ресемплинг.

## Чтобы звучало как человек

Слова и тон задаёт Plumo (`src/app/domain/phrases.py`), всё остальное — настройки агента в ElevenLabs:

| Настройка | Значение | Почему |
| --- | --- | --- |
| Голос | живой мужской голос из Voice Library, не «дикторский». Сейчас «Maxim — Conversational & Natural» (`ELEVENLABS_VOICE_ID=6YjFofyVXU1ASguf2hTJ`, русский) | персона — Тимур, говорит в мужском роде. Кыргызский у этого голоса не проверен |
| TTS model | `eleven_v4_turbo` или `eleven_v3_conversational`: оба говорят по-кыргызски, множитель 0.5, первый звук через ~0.2–0.3 с (замер ниже). `eleven_flash_v2_5` — только для русского | выбрать после прослушивания носителем |
| Stability | 0.4–0.5 | ниже — живее интонация, выше — монотоннее |
| Text normalisation | ElevenLabs | цифры «85 000» читает словами; модель пишет цифры, их проверяет валидатор |
| Turn eagerness | Normal | не перебивает человека на паузе |
| Interruptions | включены | клиент перебил — агент замолкает |
| Soft timeout | ~1.5 с, сообщение «Так, секунду, смотрю…» | наш ответ идёт через валидатор, пауза закрывается живой фразой |
| Silence / end call | ~15 с тишины → «Алло, вы меня слышите?» | как делает живой менеджер |
| Background sound | лёгкий офисный фон (по желанию) | меньше ощущение «робота в вакууме» |

## Номер

- **Zadarma**: виртуальный номер 312 (Бишкек) → настройки номера → External server → SIP URI `+<номер>@<sip-хост ElevenLabs>`. Неотвеченные переадресации должны отклоняться, а не возвращаться. SIP REFER у Zadarma по отзывам отдаёт 501, так что перевод на живого менеджера через REFER надо проверить заранее.
- **Telnyx**: у ElevenLabs есть готовая интеграция. Сначала проверить, есть ли номера +996 и какие документы нужны.
- Бизнес ставит переадресацию с обычного номера на виртуальный: «если не ответил» или «всегда». Для пилота «пропущенный звонок» хватит «если не ответил / занято».


## Что ядро делает со звонком

- **Числа словами → цифры.** STT пишет «восемьдесят пять тысяч», «сексен беш миң», «одиннадцать», а поиск по базе и валидатор сверяют цифры. Реплика канала `voice` переводится в цифры (`src/app/domain/spoken_numbers.py`), услышанный текст сохраняется в `metadata.stt_text`. Одиночные «один», «бир», «он» остаются словами: «бир батир барбы» — это «есть квартира?», а не цена 1.
- **Один звонок — один диалог.** После post-call webhook диалог звонка закрывается, следующий звонок начинает новый. Память клиента общая для всех диалогов.
- **Менеджер взял диалог, а на линии его нет** — агент не молчит, а говорит «вашим вопросом уже занимается менеджер, он перезвонит».
- **Бизнес звонка** определяется по набранному номеру (`contacts.voice_numbers`). Если номер ничей и бизнесов несколько, агент говорит фразу-заглушку и не угадывает чужой бизнес. Бизнес записывается в `voice_calls.business_id`, поэтому `/metrics?business_id=` считает звонки по бизнесу.
- **Задержка.** Из post-call webhook сохраняются метрики платформы по каждой реплике (`convai_llm_service_ttfb` — сколько ElevenLabs ждала первый токен от Plumo, `..._ttf_sentence`) и сводка p50/max в `voice_calls.metadata.latency`. Шаги ядра пишутся в `interaction_logs.timings`: `prepare_ms`, `model_ms`, `post_ms`.

## Проверка речи

```powershell
.\dev.cmd voice                          # фразы ru / ky / смесь: TTS → μ-law 8 кГц → Scribe
.\dev.cmd voice --forced-language         # плюс распознавание с заданным языком
.\dev.cmd voice --audio-dir recordings\   # свои записи: <имя>.wav + <имя>.txt (эталон) + <имя>.lang (ru/ky/mixed)
```

Скрипт синтезирует фразы сразу в телефонном формате, как их везёт SIP, и распознаёт Scribe. По каждой фразе он печатает WER, сохранились ли ключевые сущности (цена, улица, день), уверенность (среднее геометрическое вероятностей слов по `logprob`), определённый язык и задержки. WAV и `report.json` складываются в `work/voice_probe/` (не в git). Синтетическая речь чистая, поэтому её WER — нижняя граница. Решение по кыргызскому голосу принимается по реальным записям и после прослушивания носителем. Кредиты тратятся: количество символов печатается до отправки.

Замер 9 октября 2026, голос «Sarah» (premade), STT `scribe_v2`, аудио 8 кГц μ-law:

| TTS | Язык | WER авто / с языком | Первый звук TTS | STT |
| --- | --- | --- | --- | --- |
| eleven_flash_v2_5 | ru | 0.10 / 0.10 | 0.3 с (холодный старт 1.0 с) | 0.7–1.3 с |
| eleven_v3_conversational | ru | 0.13 / 0.13 | 0.26 с | 0.7–1.1 с |
| eleven_v3_conversational | ky | 0.23 / **0.10** | 0.22 с | 1.3–2.6 с |
| eleven_v3_conversational | смесь | 0.17 | 0.27 с | 1.1 с |
| eleven_v4_turbo | ru | 0.10 / 0.06 | 0.33 с | 0.8–1.8 с |
| eleven_v4_turbo | ky | 0.13 / 0.13 | 0.24 с | 1.3–1.8 с |
| eleven_v4_turbo | смесь | **0.58** | 0.24 с | 1.3 с |

Что из этого следует:

- Почти весь WER на ru и ky — **числа словами**: «85 000» → «восемьдесят пять тысяч», «$85 тыс.». Без них кыргызская фраза звонящего распознана без ошибок. Поэтому ядро и переводит числа в цифры.
- Заданный язык `ky` помогает кыргызскому: WER 0.23 → 0.10, уверенность определения языка 0.59 → 1.0. Но звонящий смешивает языки, так что фиксировать язык агента стоит только для клиента, о котором известно, что он говорит по-кыргызски. Это уже делает `/initiation` по карточке.
- **Смешанная речь — слабое место**: в одном прогоне STT принял её за русский с вероятностью 0.47 и записал кыргызские слова казахскими буквами («маға», «шейін»). Это прямо попадает в критерий продукта «WER на смеси > ~20% — кыргызский голос не продаём». Нужен тест на реальных записях.
- `eleven_flash_v2_5` для кыргызского не годится, у него нет этого языка.
- Batch-STT здесь медленнее, чем realtime STT, который использует агент. Задержку звонка смотреть по `voice_calls.metadata.latency`.

## Чего пока нет

- Перевод звонка на живого менеджера (`transfer_to_number`). Сейчас агент говорит «передам менеджеру», handoff уходит в очередь, менеджер перезванивает. SIP REFER у Zadarma не проверен.
- Уверенность распознавания в живом звонке: Custom LLM получает от ElevenLabs только текст. Ядро уже умеет её принять (`metadata.stt_confidence`, низкая → большая модель), но платформа её не передаёт.
- Номера бизнеса в `contacts.voice_numbers` пока заполняются вручную, в БД или seed.
- `VOICE_USD_PER_MINUTE` — заполнить по тарифу ElevenLabs, иначе `voice_cost_per_minute` в `/metrics` будет 0.
- Тексты приветствия и фразы на кыргызском должен вычитать носитель, WAV из `work/voice_probe/` — прослушать.
