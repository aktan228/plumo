# Стенд оценки диалогов

`python -m app.dialog_eval` (или `.\dev.cmd dialog-eval`) прогоняет многошаговые диалоги: клиента играет дешёвая модель по карточке персоны, отвечает **всё ядро агента**, судья оценивает диалог целиком. Это даёт числа «до/после» для любого изменения промпта, ядра или модели.

Чем отличается от [`bench`](BENCH.md): `bench` проверяет одну реплику модели без ядра. Здесь агент — тот же путь, что в Telegram (`build_agent` → `process_message`, канал `telegram`, демо-бизнес), включая валидатор, подстановки ядра и передачи менеджеру. Оценивается текст, который увидел бы клиент.

## Как устроен прогон

- **Клиент** — Claude Haiku 5.5 через OpenRouter, рассуждение выключено. Видит только свою карточку и переписку, а промпт агента и данные агентства — нет. Первая реплика каждой персоны фиксирована. Клиент отвечает JSON `{message, status}`, где `status` — `continue`, `gave_contact`, `declined` или `left`. Диалог заканчивается, когда клиент ушёл, отказался или оставил телефон, либо когда исчерпан лимит `--turns` реплик агента.
- **Агент** — настоящее ядро в одной из конфигураций (`--config haiku | sonnet`, модель через OpenRouter). Резервные модели отключены: падение видно как ошибка, а не как ответ другой модели. Передачи уходят в mock-провайдер, **настоящий менеджер уведомлений не получает**. Каждый диалог — новый клиент `eval-<run>-<config>-<persona>-<n>` в локальной базе.
- **Судья** — Claude Sonnet 5.5 через OpenRouter, температура 0, рассуждение выключено. Видит правила агента, каталог, карточку клиента и переписку, но не знает, какая конфигурация отвечала.

Персоны — в [`src/app/dialog_eval/personas.py`](../src/app/dialog_eval/personas.py): семья с бюджетом, «скок» с ошибками, скептик, торгующийся, «подумаю», кыргызоязычный, смешанная речь, раздражённый, аренда вместо покупки, вопросы вне данных.

## Что считается

Детерминированные проверки (код, [`checks.py`](../src/app/dialog_eval/checks.py)):

| Метрика | Как |
| --- | --- |
| Повторы вопросов | вопрос агента похож на его прежний вопрос (пересечение основ слов ≥ 0,6) |
| Длина | средняя длина реплики, доля реплик длиннее 3 предложений |
| Язык | `detect_language` ответа против языков персоны. Детектор слаб на кыргызском, поэтому язык дублирует судья |
| Подмены ядра | доля ходов с `grounded_fallback`, `fallback:*`, `validator:*`, `empty_draft_fallback` |
| Чужие суммы | число в ответе, которого нет ни в каталоге, ни в словах клиента. **Критично** |
| Тип сделки | аренда покупателю (450 USD, «в месяц») или цена продажи арендатору |
| Передача | нет нужной (клиент оставил телефон, а передачи нет; вопросы вне данных без передачи — **критично**) и лишняя (причина, которой у персоны быть не должно) |
| Исход | телефон сохранён в базе, встреча (`schedule_meeting` или `ready_for_meeting`), клиент ушёл |
| Задержка и цена | p50/p90 хода агента; стоимость агента на диалог (симулятор и судья считаются отдельно) |

Судья ставит оценки 1–5: живость, краткость, «слушает клиента», подбор, работа с возражениями (`null`, если возражений не было), доведение до шага, честность. Дополнительно — критичная ошибка, худшая реплика и пояснение с цитатой к каждой оценке.

Судья — модель того же семейства, что и агент, поэтому может предпочитать свой стиль, особенно при оценке конфигурации `sonnet`. Детерминированные проверки от модели не зависят.

## Запуск

Нужен Postgres (`./dev.sh db`). Для живого прогона нужен `OPENROUTER_API_KEY` с балансом. Перед расходом стенд печатает оценку (верхняя граница: каждый диалог идёт до лимита реплик) и ждёт `y`. Затем бесплатно проверяет ключ и баланс.

```bash
python -m app.dialog_eval --mock                                   # без сети, бесплатно
python -m app.dialog_eval --config haiku --repeat 2                # 20 диалогов, оценка до ~$0.5
python -m app.dialog_eval --config haiku sonnet --persona family skeptic haggler thinker kyrgyz --repeat 1
python -m app.dialog_eval --config haiku --turns 8 --yes           # без вопроса о расходе
```

Порядок цен (OpenRouter, 24.10.2026: Haiku 5.5 — $0.10/$0.50, Sonnet 5.5 — $2/$10 за 1M токенов), верхняя граница на диалог из 10 реплик:

| | агент | клиент | судья | итого |
| --- | --- | --- | --- | --- |
| haiku | ~$0.004 | ~$0.002 | ~$0.019 | ~$0.025 |
| sonnet | ~$0.080 | ~$0.002 | ~$0.019 | ~$0.10 |

Результат — в `work/dialog_eval/<время>/`:

- `report.md` — итог по конфигурациям, оценки судьи, разбивка по персонам и худшие диалоги целиком;
- `results.json` — сырые данные.

Тесты: `tests/unit/test_dialog_eval.py` — на каждую проверку пара «хороший / плохой» диалог; `tests/integration/test_dialog_eval_pipeline.py` — весь конвейер в `--mock` через Postgres. Новая персона добавляется в `personas.py` вместе с `mock_lines`.
