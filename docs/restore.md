# Восстановление из backup и его проверка

Восстановление выполняет тимлид или junior в явно выделенной изолированной среде. Доступ к backup и к ключу шифрования `CHANNEL_SECRET_KEY` контролирует тимлид. Цели потери данных (RPO) и времени восстановления (RTO) согласует тимлид; достигнутыми их можно назвать только по измерению на staging.

## Правила среды восстановления

Копия содержит настоящие диалоги, задания в очереди и зашифрованные токены ботов. Если на ней запустить worker с рабочим ключом, он отправит накопленные ответы и уведомления реальным клиентам и менеджерам.

- **Worker не запускать.** У API `CHANNEL_WORKER_ENABLED=false`; отдельного `python -m app.worker` нет.
- `AI_MODE=mock`, `HANDOFF_PROVIDER=mock`, `APP_ENV=development`.
- Не задавать `TELEGRAM_BOT_TOKEN`, `RESEND_API_KEY`, `INSTAGRAM_*`, `PUBLIC_BASE_URL`, `OPS_TOKEN` рабочего стенда.
- `CHANNEL_SECRET_KEY` — только для проверки, что токены открываются. Значение не печатать и не сохранять в файлы.
- Отдельная БД; её адрес не совпадает с рабочим.

## Порядок

1. **Перед backup** (на исходной БД): снимок количества строк.
   ```sh
   cd backend
   DATABASE_URL=<исходная БД> python -m app.restore_check --snapshot > counts.json
   ```
   `counts.json` содержит только числа и время. Данные, пришедшие после снимка, дадут расхождение в большую сторону — это не ошибка восстановления.
2. Backup средствами провайдера, или `pg_dump -Fc -f plumo.dump <исходная БД>`.
3. Создать пустую изолированную БД и восстановить: `pg_restore --no-owner -d <копия> plumo.dump`. Записать время начала и конца.
4. Проверить копию:
   ```sh
   DATABASE_URL=<копия> CHANNEL_SECRET_KEY=<ключ стенда> python -m app.restore_check --expect counts.json
   ```
5. Записать результат в таблицу ниже. После проверки удалить копию, если тимлид не решил иначе.

## Что проверяет `python -m app.restore_check`

Модуль [restore_check.py](../backend/src/app/restore_check.py) работает в транзакции только для чтения и выводит только числа и статусы.

| Проверка | Провал |
|---|---|
| `schema_version` равна head кода | копия от другой версии схемы |
| бизнесы, операторы, активные материалы, версии сценария, клиенты, диалоги, сообщения, передачи, подключённые каналы, подтверждённые менеджеры | число не равно снимку |
| диалог, сообщение и передача принадлежат одному клиенту и бизнесу | связь между бизнесами |
| нет свежего heartbeat | на копии работает worker |
| зашифрованные токены каналов открываются ключом | ключ не тот или нет ключа при сохранённых токенах |
| задания и ответы в очереди | не провал, только число: столько отправит worker, если его запустить |

Время последнего сообщения в копии показывает, насколько backup старше момента восстановления.

| тот же запуск с другим ключом | `FAIL channel tokens … 0 of 1` |
| свежий heartbeat в копии | `FAIL no worker on this copy` |
| интеграционный тест `tests/integration/test_restore_check.py` | passed |

Время на настоящем объёме и на хостинге не измерено.
