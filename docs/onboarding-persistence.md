# Сохранение и восстановление мастера настройки

`/create/wizard` сохраняет текущий шаг, поля бизнеса и агента, оформление и логотип, материалы TXT/MD/FAQ/ссылки, сценарий, выбранный канал и параметры тарифа. Частично набранный источник тоже сохраняется. Гостевой разговор остаётся сценарным демо. В аккаунте тестовый чат теперь использует ядро и отдельную сохраняемую историю: [описание этапа 5](agent-test-chat.md).

## Посетитель и аккаунт

- Гостевое демо автоматически сохраняется в `sessionStorage` этой вкладки и восстанавливается при перезагрузке. Закрытие вкладки может удалить его; настройки по-прежнему можно экспортировать в JSON. Если браузер запретил storage, показана ошибка сохранения.
- В аккаунте данные загружаются и сохраняются в PostgreSQL по `business_id` из проверенной сессии. Во входящем теле такого поля нет, дополнительные поля backend отклоняет. Черновик доступен после нового входа и на другом устройстве.
- Если в текущей вкладке есть гостевое демо, а серверный черновик ещё пустой, мастер предлагает явно перенести его в аккаунт. Автоматического смешивания гостевых данных с существующим бизнесом нет. После успешного переноса гостевая копия удаляется.
- Если backend не отвечает, мастер показывает ошибку загрузки и повторную попытку. Он не подменяет недоступный аккаунт пустым гостевым черновиком.

## Сохранение и конфликты

Изменения сохраняются после паузы в 600 мс, переход на следующий шаг и кнопка «Сохранить» отправляют текущие изменения сразу. Запросы одной вкладки выполняются последовательно, более новые изменения остаются в очереди до подтверждения. Уход по ссылкам мастера на сайт/в кабинет предварительно сохраняет изменения; при несохранённых данных браузеру запрашивается предупреждение перед закрытием или перезагрузкой.

Каждая запись имеет `version`. Если другая вкладка уже обновила её, backend отвечает 409 `version_conflict`; автоматическая перезапись останавливается. Можно скачать свои настройки или явно загрузить серверную версию. Экспорт JSON дополнительно содержит `wizardSnapshot`: полный локальный снимок, включая логотип и ещё не добавленный текст источника. Повтор ранее принятого запроса с теми же данными возвращает сохранённую запись без добавочного изменения версии.

При временной ошибке изменения остаются на экране, доступна кнопка сохранения. При истечении сессии можно скачать несохранённые изменения и войти заново. Уже подтверждённые сервером данные восстанавливаются после входа.

## Завершение настройки

На шестом шаге есть «Завершить настройку». Обязательны источник и заполненные название/описание бизнеса, имя агента, приветствие, задача и fallback. Набранный, но ещё не добавленный источник нужно сначала добавить или очистить.

Одна транзакция отмечает черновик завершённым и сохраняет название/описание бизнеса, `contacts.assistant_name` и снимок настроек в `profile.onboarding` (без дублирования двоичных данных логотипа). Остальные контакты и профиль сохраняются. Повторное завершение безопасно. Новые изменения остаются черновиком до следующего явного завершения. В мастер можно вернуться из пункта «Настройки» кабинета.

Завершение настройки публикует тексты, FAQ и TXT/MD в `knowledge_items` своего бизнеса и применяет параметры агента. Оно не включает каналы и не читает сайты. Знания, добавленные вручную или другим импортом, сохраняются; заменяются только записи предыдущей публикации мастера. [Применение настроек](business-agent-settings.md). Тестовый чат мастера остаётся сценарным до следующего этапа.

## API

| Метод | Путь backend | Назначение |
| --- | --- | --- |
| GET | `/api/v1/onboarding` | Текущий черновик своего бизнеса; для старого аккаунта создаётся пустой |
| PATCH | `/api/v1/onboarding` | `{version, step, data}`: сохранить снимок |
| POST | `/api/v1/onboarding/complete` | `{version}`: завершить настройку и сохранить карточку бизнеса |

Ответ: `{business_id, step, data, version, completed_at, published, knowledge_count, updated_at}`. `published=true` означает, что текущая версия применена к агенту; `knowledge_count` — число опубликованных фрагментов материалов. `data=null` означает новый пустой черновик. `data` содержит `settings`, `sources`, `entry`, `channel` и `pricing`. Шаг — 0–5. Browser обращается через закрытый Next.js BFF `/api/plumo/onboarding`; сервисный API key остаётся на сервере.

Ограничения: 10 источников, 100 000 байт UTF-8 на источник с вопросом, 200 000 байт суммарно; вопрос и заголовок до 300 символов. Логотип — inline PNG/JPEG/WebP до 1 000 000 байт, SVG и внешние URL не принимаются. Для этого PATCH BFF читает поток до 2 000 000 байт; прежние маршруты сохраняют предел 100 000 байт. Проверяются origin, маркер запроса и сессия; ошибки данных — 422, конфликт версии — 409, слишком большое тело — 413.

## Деплой

Новых сервисов и переменных окружения не нужно. Сначала backend с миграцией `009_onboarding_persistence` (`alembic upgrade head`, Docker выполняет при запуске), затем frontend той же версии. Миграция добавляет версию и дату завершения к уже созданным черновикам, сохраняя их содержимое.

Проверка: заполнить несколько шагов, дождаться статуса сохранения, перезагрузить страницу, выйти и войти снова. Настройки и шаг должны восстановиться. Изменение в двух вкладках должно показать конфликт; завершение — обновить название бизнеса в кабинете.
