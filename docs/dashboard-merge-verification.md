# Проверка объединения кабинета и каналов

Дата: 24 октября 2026. База: `main` (`c6903ac`). Включённая ветка: `feature/dashboard-telegram-instagram` (`cd455a2`).

## Результат объединения

- Сохранены компактная оболочка, меню, пустой канбан, RU/EN и мобильная навигация из `main`.
- Режим «Список» использует серверную переписку из ветки интеграций. Компонент остаётся смонтированным при переключении вида и разделов; его опрос API приостанавливается, когда список скрыт.
- Сохранены защита `/dashboard` серверной сессией, вход/выход оператора, API-прокси и изоляция по бизнесу.
- Telegram/Instagram используют серверные состояния и мастера подключения. Баннер ИИ отражает состояние подключённых каналов; «Настроить ИИ» открывает интеграции.
- WhatsApp остаётся демонстрационным мастером. Новые разделы и действия без реализации показывают `soon`. Стадии канбана пока не связаны с сервером.
- Конфликты в оболочке, переписке, иконках и двух README разрешены вручную; новый дизайн сохранён.

## Границы проверки

Для текущего прогона запущен отдельный PostgreSQL на `127.0.0.1:55432`. Рабочая БД, существующий PostgreSQL и локальные `.env` не изменялись. Браузерный стенд использовал отдельного QA-оператора, модель `mock` и HTTP-имитации Telegram/Instagram из тестов. В реальные каналы сообщения не отправлялись. Живой Instagram в этом объединении не проверялся; предшествующие результаты живого Telegram и ограничения описаны в [dashboard-channels.md](dashboard-channels.md).

Проверка миграции выполнялась на новой БД. На рабочую БД миграция не применялась. Для запуска объединённого кабинета нужны миграция `006_channels_dashboard`, созданный оператор, API, отдельный worker и серверные настройки frontend по [инструкции](dashboard-channels.md).


## Исправление запуска на Python 3.12 — 25 октября 2026

Первоначальные проверки объединения выполнялись на Python 3.14. При первом деплое Render использовал Python 3.12 из Dockerfile: импорт API падал в `DialogQueries.messages_page`, поскольку метод класса `list` перекрывал встроенный `list` при вычислении аннотации `tuple[list[Message], str | None]`.

В `dialog_queries.py` включено отложенное вычисление аннотаций (`from __future__ import annotations`). Запросы и схема БД не менялись.

Проверки исправления:

- Исходная ошибка воспроизведена на Python 3.12.10 до изменения.
- После изменения API и worker импортируются; unit-набор на Python 3.12.10: **139 passed**.
- Backend собран и установлен обычным wheel-пакетом в изолированное окружение Python 3.12.10.
- Uvicorn запущен из установленного пакета с `APP_ENV=stand` и тестовыми ключами: `GET /health` — **200**, `{"status":"ok"}`; запрос к защищённому API без ключа — **401**.
- Рабочая БД и внешние провайдеры в проверке не использовались. Linux Docker-образ в этом локальном прогоне не запускался; окончательный результат деплоя подтверждается логами Render и его публичным `/health`.
