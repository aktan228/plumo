# Dashboard и main: объединение 4 ноября 2026

Исходные версии: Dashboard `98a3290`, main `12aa8b3`. Сохранены разделы DB-01–DB-11 и работа main по привязке менеджеров, статусам доставки, лимитам, мониторингу, заявкам пилота и выполнению модели вне транзакции. Сохранено обновление Next.js до 16.4.4.

## Разрешение конфликтов

- Единственная ORM-модель `manager_recipients` использует поля main. Совместимые имена старого Dashboard API отображаются на те же столбцы; отключение и изменения через новый API повышают версию для старого API.
- Интерфейс использует Manager Notifications из main. Обратные вызовы принимают оба формата одноразовых кодов с аутентификацией соответствующего endpoint. Подтверждённый получатель общий для обоих API.
- Новые задания уведомлений используют состояния handoff из main. Прежний ledger продолжает обрабатываться с его поколением, без слепого повторения неопределённой отправки. Поздний результат нового механизма также проверяет поколение; ручное решение и повтор его меняют. Worker и resolver соблюдают порядок блокировок job → handoff.
- При ошибке Telegram 5xx после отправки, отсутствии корректного receipt или неопределённом результате запись остаётся unknown и требует ручного решения. 429 и ошибки до отправки сохраняют ограниченный безопасный повтор.
- Сохранены история клиента, черновики ответов, URL-переходы, состояния уведомлений и действия из main в карточке диалога.

## Миграции

Уже существующие в main миграции 013–017 сохранены без изменения. Dashboard следует после них:

1. `018_dashboard_manager_compat`: версия получателя, поколение уведомления, прежний ledger.
2. `019_pipeline_stage`: канбан.
3. `020_improvements`: замечания.
4. `021_scenario_revisions`: история сценариев.

Проверены установка 001→021, полный откат →base→021 на пустой отдельной БД и путь main 017→021→017→021. `alembic heads` возвращает единственный head 021.

Старый локальный стенд ветки Dashboard использовал другие определения 013–016. Его нельзя считать базой main или обновлять обычным upgrade после переименования. Для локального стенда нужен отдельный перенос либо новая синтетическая БД с этой цепочкой. Production-схема и данные в этой задаче не менялись.
