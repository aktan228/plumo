# DB-05: рабочий сценарий менеджера

Реализация интерфейса: 2 ноября 2026. Ручная, мобильная и живая приёмка ещё не выполнены.

Из уведомления или списка оператор открывает диалог своего бизнеса. Выбор отражается в URL; назад/вперёд переключают диалоги, сбрасывая чужую загруженную историю. Мобильная кнопка «К списку» убирает выбор из URL. Черновики сохраняются отдельно для каждого диалога в памяти страницы; закрытие/обновление страницы с вводом вызывает стандартное предупреждение браузера. Постоянное хранение клиентских текстов в браузере не добавлялось.

«Взять» останавливает автоответы по существующему серверному контракту. «Вернуть агенту» предупреждает об отмене неотправленных ответов менеджера. После успешного действия UI применяет возвращённую версию режима и перепроверяет доступность ответа. Устаревший poll с меньшей версией не откатывает режим. Сервер остаётся источником полномочий и состояния.

Ответ менеджера имеет один idempotency key. При неопределённом HTTP-результате повторяются исходный текст и ключ, даже если оператор уже изменил черновик. Новый черновик остаётся в редакторе после восстановления исходной операции. При подтверждённом отказе 4xx (кроме timeout/rate limit) pending снимается, текст сохраняется. После принятия сервером редактор очищается только если оператор не изменил текст во время запроса. Повторная отправка через канал после delivery unknown отдельно предупреждает о риске дубликата.

Список обновляется через последовательные курсоры до запрошенного числа карточек: лимит API в 100 записей на запрос не обрезает ранее раскрытые страницы. Смена фильтра начинает с первой страницы; повтор курсора прекращает загрузку с ошибкой, а не зацикливает запросы.

В карточке клиента есть история его диалогов и последние 100 сообщений, полученные через существующий tenant-scoped API. Выбор диалога возвращает в рабочий чат. Отдельно подписан непроверенный номер, указанный клиентом в сообщении. История не объединяет клиентов по телефону.

Проверки frontend покрывают восстановление отправки с изменённым вводом, сохранение нового черновика после подтверждения, курсоры за пределами 100 записей, пересечения страниц и повторяющийся курсор. Backend-контракт истории и изоляция покрыты существующими integration-тестами; полный набор 347/347 прошёл до этого изменения интерфейса.

Живая приёмка: обращение → передача → уведомление нужному менеджеру → ссылка через вход → захват → ответ в исходный канал → возврат агенту. Проверить два бизнеса, узкий экран, клавиатуру, потерю сети, unknown и смену режима во второй вкладке. Для настоящего Telegram нужны служебный webhook и публичный HTTPS-адрес API; проверка getMe сама по себе доставку не подтверждает.
