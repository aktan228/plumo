# Публикация материалов и применение настроек агента

Мастер сохраняет черновик автоматически. «Завершить настройку» применяет текущий снимок к рабочему бизнесу и базе знаний. До этого редактирование не меняет действующие ответы агента.

## Что применяется

| Поле мастера | Эффект |
| --- | --- |
| Название и описание | Карточка бизнеса и факты в контексте модели |
| Аудитория и сценарий sales/support | Контекст задачи, поддержка не навязывает продажи |
| Имя | `contacts.assistant_name`, инструкции и раскрытие ИИ в первой реплике |
| Приветствие | Первая чистая реплика приветствия нового чата и Telegram `/start`; правила проверки фактов сохраняются |
| Язык | Основной язык при неизвестном языке сообщения; явный язык клиента и hint учитываются |
| Тон | Дружелюбный/деловой стиль в инструкциях модели |
| Цель | Задача в инструкциях вместо общего шаблона |
| Если ответа нет | Серверный fallback при неподтверждённом факте; проверяется существующим валидатором |
| Когда передавать сотруднику | Дополнительные условия в инструкциях модели, `handoff_required` проходит обычный механизм передачи |

Просьба клиента о человеке, границы данных, раскрытие ИИ, запрет неподтверждённых бронирований и переводов остаются обязательными. Небезопасный текст приветствия или fallback заменяется штатным безопасным ответом. Голосовой канал сохраняет свои правила начала звонка и краткости. Настройки хранятся отдельно в `businesses.profile.agent_settings`, а не читаются из незавершённого черновика.

## Материалы

Текст, FAQ и содержимое загруженных UTF-8 TXT/MD публикуются в `knowledge_items` с `business_id` из сессии. FAQ сохраняет вопрос и утверждённый ответ. Материалы длиннее 2400 символов разделяются на части с небольшим пересечением; текущий поиск отдаёт до пяти релевантных частей, чтобы размер контекста не рос до полного загруженного файла.

Действуют прежние серверные ограничения: максимум 10 источников, 100 000 байт UTF-8 на источник и 200 000 суммарно. Адрес сайта/Instagram остаётся ссылкой в настройках; сайт не скачивается и его содержимое не выдумывается. Если есть только ссылки, интерфейс прямо предлагает добавить текст, FAQ или файл.

Повторная публикация заменяет только записи, помеченные `metadata.origin=plumo-onboarding-v1` в своём бизнесе. Ручные знания и данные других бизнесов не затрагиваются. Идентификаторы частей стабильны для источника; конфликт заголовка с ручной записью разрешается новым названием. Замена материалов, профиль и дата завершения фиксируются одной транзакцией. Сбой возвращает прежние рабочие знания и настройки.

`profile.onboarding_publication` хранит применённую версию черновика и число частей. Ответ API мастера содержит `published` и `knowledge_count`. Повтор принятого завершения не дублирует записи. Если настройка завершалась до подключения публикации, нужно снова нажать «Завершить настройку»: старый снимок будет применён к базе знаний.

## Проверка и граница этапа

Интеграционные тесты проходят через API сохранения/публикации и настоящее ядро: смена имени/приветствия, обновление ответа FAQ, fallback, разделение бизнесов, параметры, получаемые LLM, передача человеку, ограниченный контекст и откат при сбое. Провайдер модели в тестах управляемый, внешние вызовы не оплачиваются.

Пункт 5 теперь подключает браузерный тестовый чат аккаунта к тому же ядру, отдельной истории тестов и лимитам расходов: [описание](agent-test-chat.md). Гостевой пример остаётся локальным. В подключённых рабочих каналах ядро уже использует опубликованные настройки и знания.

Новой миграции и новых переменных окружения для пункта 4 нет. Нужны миграции 007–009 предыдущих этапов, настроенный API и провайдер модели для живых ответов. Сначала обновляется backend, затем frontend.
