# DB-06: Testing и проверки перед запуском

Реализовано 2 ноября 2026. Изменение не требует миграции БД. Frontend и backend выпускаются вместе.

Тестовая сессия показывает свою `publication_version` и текущую версию публикации. Listing возвращает `publication_version`, detail дополнительно возвращает `current_publication_version` и `stale`. История прежней версии сохраняется; после новой публикации обычная отправка в старый тест блокируется. Проверка обновляется при открытии, возврате фокуса и каждые 15 секунд видимой страницы. Серверная проверка версии остаётся обязательной и защищает промежуток между обновлениями UI. Восстановление уже созданного запроса по прежнему request_id сохраняет существующий idempotency-контракт.

У каждого ответа показаны модель и тип: демо, правило без вызова модели или ответ модели. Использованные источники ведут к конкретному опубликованному фрагменту в Knowledge Base; валидный ID сохраняется через вход. Отключённый или заменённый источник отмечается как недоступный в текущей публикации. Передача в тесте обозначена как симуляция без реального уведомления менеджеру.

Панель называется «Проверки перед запуском». Четыре пункта отражают технические условия, а не принятие качества. Успешный тест подписан «Ответ модели получен». API явно возвращает `technical_only: true` и `quality_accepted: false`; механизма приёмки качества в этом изменении нет. Демо, ответ правила и тест старой версии по-прежнему не считаются доказательством ответа живой модели текущей версии.

Получатель менеджера проверяется отдельно: конфигурация служебного Telegram-провайдера и подтверждённая привязка только своего бизнеса. Никакие chat_id или токены в readiness не возвращаются. Даже подтверждённая привязка требует живой проверки доставки. Она не добавляется в счётчик 4/4, чтобы не менять смысл существующих пунктов.

Сессия с датой, версией, статусами попыток, моделью и источниками служит технической историей проверки. Качество J-03, эталонные ответы и языковая приёмка оформляются командой отдельно; новый eval-фреймворк и автоматическое принятие качества не создавались.

Проверки: frontend-регрессии сравнения версий и валидации ссылок; integration старого теста после публикации, новой версии, доступа другого бизнеса, демо/правил, канала и tenant-scoped получателя менеджера. Результаты запусков записаны в `PLUMO_DASHBOARD_PROGRESS.md` рабочей папки задачи. Визуальная, мобильная и живая приёмка не подтверждаются этими тестами.
