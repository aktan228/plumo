# Frontend Plumo

Создан минимальный Next.js (App Router) + TypeScript frontend с Motion. Tailwind CSS подключён через PostCSS без Preflight: существующий CSS сохраняется. Новые компоненты оформляем utility-классами Tailwind; shadcn/ui пока не подключён. Цветовые токены: plumo-blue, plumo-ink, plumo-muted, plumo-line, plumo-soft. Конфигурация — postcss.config.mjs и src/app/tailwind.css.

Основная библиотека интерфейсных иконок — Hugeicons Stroke Rounded: `@hugeicons/react` и `@hugeicons/core-free-icons`, бесплатный набор под MIT. Общий компонент `src/components/ui/plumo-icon.tsx` задаёт толщину линии 1.7 и скрывает декоративные иконки от скринридеров. Мастер WhatsApp Business использует библиотечные иконки телефона, облака, диалогов, истории, оплаты, проверок и навигации; фирменный логотип WhatsApp Business сохранён отдельно. Другие существующие экраны переводятся постепенно по задачам.

## Запуск

Из папки frontend (Node.js 20.9 или новее):

```powershell
npm install
npm run dev
```

Открыть http://localhost:3000. Команда `npm run typecheck` проверяет TypeScript, `npm run build` собирает приложение. Сервер при реализации хедера не запускался.

## Что реализовано

- Объединённый `/dashboard`: компактное меню и пустой канбан по референсу Pleep из `main`; серверная авторизация, реальные Telegram/Instagram и переписка из ветки интеграций. Кабинет открывается на канбане, режим «Список» показывает диалоги из API. Переключение вида и разделов сохраняет черновики переписки и мастеров. Новые разделы и неподключённые действия показывают `soon`; стадии воронки пока не связаны с сервером. Баннер показывает полученное с сервера состояние ответов ИИ, «Настроить ИИ» открывает интеграции; есть имя бизнеса, оператор и выход. Сохранены RU/EN, мобильное меню, Hugeicons и токены Plumo.


Кабинет работает с backend через сервер Next.js: браузер обращается только к `/api/auth/*` и `/api/plumo/*` (белый список маршрутов в `src/lib/api/routes.ts`), сервер добавляет `PLUMO_API_KEY` и сессию оператора из HttpOnly cookie. Для запуска нужен `.env.local` с `PLUMO_API_URL` и `PLUMO_API_KEY` (образец — `.env.example`; префикс `NEXT_PUBLIC_` для них запрещён) и запущенные API и worker. Настройка каналов: [../docs/dashboard-channels.md](../docs/dashboard-channels.md).

- Раздел «Интеграции» (src/features/dashboard/integrations.tsx). Telegram и Instagram показывают состояние с сервера: подключён, требуется действие, ошибка, отключён; аккаунт и ссылку на бота, время проверки и последнего сообщения, последнюю безопасную ошибку. Подключение выбирает серверную конфигурацию (токен в браузер не попадает) и показывает готовность сервера; конфликт webhook Telegram подтверждается отдельной кнопкой. Действия: подключить, проверить, включить/выключить агента, отключить (с подтверждением), подключить снова. Кнопки блокируются на время запроса, ошибки показываются текстом. Статусы обновляются каждые 15 с. WhatsApp Business — прежний демонстрационный мастер.

- WhatsApp Business использует отдельный мастер (src/features/dashboard/whatsapp-setup.tsx) по скриншотам Pleep. Две колонки, индикатор из четырёх шагов, карточки с выбором и иллюстрациями, пояснения справа, закреплённые кнопки снизу на широком экране. Ветка с телефоном проверяет наличие WhatsApp Business; обычный WhatsApp показывает подготовку перехода и требует подтверждения его завершения. Облачная ветка пропускает этот шаг. Затем выбирается предпочтительная оплата: напрямую в Meta или расчёт через Plumo по согласованию. Фиксированные тарифы Pleep не перенесены; на экране есть ссылка на [официальные тарифы Meta](https://whatsappbusiness.com/products/platform-pricing/). Четвёртый экран показывает выбранные параметры и будущий вход через Facebook; кнопка отключена до настройки Meta. «Сохранить параметры» сохраняет только локальный черновик и не отмечает канал подключённым. Выбор остаётся при смене языка и возврате в каталог; перезагрузка его сбрасывает. Четвёртый экран — продолжение Plumo, поскольку финальный этап Pleep не был предоставлен. Точные условия Coexistence, импорта истории и оплаты требуют проверки перед подключением реального провайдера.

- `/dashboard` — закрытая страница: сервер проверяет сессию через backend и без неё ведёт на `/login`. Оболочка показывает бизнес и оператора, кнопку выхода и пометку mock-модели. «Диалоги» (src/features/dashboard/dialogues.tsx) загружают данные бизнеса из API: поиск, фильтры канала и режима и пагинация на сервере; список обновляется каждые 4 с, открытый диалог — каждые 3 с; опрос не идёт параллельно, останавливается в скрытой вкладке и замедляется при сбоях. История с подгрузкой ранних сообщений, время в Asia/Bishkek. «Взять диалог» и «Вернуть агенту» меняют режим на сервере. Ответ менеджера — одна операция с ключом идемпотентности: при сбое черновик остаётся, повтор того же текста не создаёт вторую отправку; под репликой — статус доставки (в очереди, отправляется, принято каналом, не отправлено, статус неизвестен, отменено) и действия для `unknown`/`failed`. Прочтение хранится на сервере и не означает прочтения клиентом. Пустой список, загрузка и недоступность API показываются явно, демо-данных нет. `/login` выполняет настоящий вход; регистрации и восстановления пароля нет (доступ выдаёт команда).

- Кнопки демо и бесплатной пробы в hero, все кнопки тарифов и завершающий CTA открывают общее меню (src/components/landing/demo-choice.tsx): помощь сотрудника либо самостоятельный просмотр сценария. Нативный dialog поддерживает Escape, закрытие по фону, удержание и возврат фокуса; блокируется прокрутка фона. RU/EN, адаптивная вёрстка и reduced motion. Самостоятельный путь ведёт в /create/wizard: источники → бизнес → оформление → агент → сценарий → тест. Есть готовый пример, свои вопросы-ответы, TXT/MD до 100 КБ, логотип и цвет, редактируемый сценарий и экспорт JSON. Для гостя настройки сохраняются в sessionStorage текущей вкладки; после входа — в PostgreSQL своего бизнеса. Гостевой разговор остаётся в памяти вкладки; история тестов аккаунта сохраняется на сервере. Кнопка «Завершить настройку» сохраняет карточку бизнеса, публикует тексты/FAQ/TXT/MD в базу знаний и применяет параметры агента, включая дополнительные условия передачи человеку; в мастер можно вернуться через «Настройки» кабинета. Детали — [../docs/onboarding-persistence.md](../docs/onboarding-persistence.md). Гостевой чат использует точные FAQ; в аккаунте тест подключён к ядру и выбранному провайдеру, история сохраняется отдельно от клиентов и действует бюджет бизнеса. Раздел «Тестирование» кабинета открывает тот же чат; [подробности](../docs/agent-test-chat.md). Ссылки входят в настройки, чтение сайтов не подключено. Тест аккаунта использует настроенный сервером провайдер модели. После теста есть форма обсуждения с сотрудником. Ветка сотрудника открывает форму подготовки письма в том же модальном окне поверх сайта; выбранные параметры тарифа и путь знакомства включаются в черновик. Отправку письма выполняет посетитель; серверного получения заявки нет. План развития и анализ Pleep — docs/demo-onboarding.md в корне проекта.

- Третий блок «От разговора — к следующему шагу» (src/components/landing/dialogue-to-lead.tsx) заменяет прежний пример с выбором готового вопроса на якоре #demo. Чат WhatsApp слева использует тот же оригинальный фон, шапку, зелёные сообщения, галочки и поле ввода, что в предыдущем блоке. Сообщения клиента набираются в поле и отправляются, ответы Plumo появляются в чате; диалог заполняет заявку справа; поля появляются после соответствующих реплик клиента. Желаемая суббота ожидает подтверждения менеджера. «Открыть переписку» раскрывает полную историю и приостанавливает анимацию. Сценарий повторяется после паузы, вне экрана и в скрытой вкладке таймер приостановлен; при prefers-reduced-motion всё показано статично. RU/EN, адаптивная компоновка, Tailwind + Motion. Данные вымышленные, backend и уведомления не вызываются.

- Кастомная 404 (src/app/not-found.tsx): чёрный фон, анимация восьми белых точек по мотивам Scene.gif, RU/EN и возврат на главную. Анимация написана на Motion, исходный GIF не используется; водяного знака нет. При prefers-reduced-motion круг статичен.

- Первый экран: крупный заголовок «Ваш ИИ-ассистент для бизнеса» и кнопки слева, чёрное окно сценарного чата с пиксельным аватаром справа. На desktop видно около 60% окна, остальное скрывается размытием; при наведении окно выезжает влево поверх части заголовка, раскрывается и показывает синий курсор. У окна полупрозрачная стеклянная поверхность с backdrop-filter; значок панели позволяет раскрыть и свернуть его нажатием, Escape закрывает. На узких экранах чат находится под текстом. Набор текста клиента, отправка, индикатор ответа и постепенное появление текста Plumo. RU/EN, адаптивная компоновка, статичный диалог при prefers-reduced-motion. Анимация приостанавливается вне экрана и в скрытой вкладке; внешние API не вызываются.

- Общие стили кнопок в src/components/ui/button-motion.css: волна заливки слева направо на hover и клавиатурном фокусе, белые кнопки переходят в чёрные, синие — в белые с рамкой. Отключённые кнопки не анимируются; prefers-reduced-motion отключает переходы. Используются Motion (motion/react) и CSS; Anime.js не подключён.

- Основной фирменный акцент — синий #2B55FF; светлая подложка #EDF1FF. Цвет задан общим токеном --blue и используется через Tailwind plumo-blue. Белые кнопки с чёрной рамкой сохранены.

- Второй блок «ИИ-агент работает, пока вас нет» / «An AI agent works while you’re out» (src/components/landing/customer-situations.tsx и messenger-preview.tsx): три макета WhatsApp, Telegram и Instagram. Заголовок по центру, без ярлыков демо и подписей сценариев; общее пояснение о сценарном характере находится под блоком. Чёрный знак Plumo, корректный знак WhatsApp из Simple Icons, оригинальные узоры фонов WhatsApp и Telegram сохранены локально (источники: public/images/messengers/README.md). Набор вопроса в readonly-поле → анимация отправки → индикатор печати → появление и набор ответа. Самолётик отправляет готовый пример; сценарии зациклены: после полного ответа — пауза 4 секунды, плавное скрытие сообщений и новый цикл. Кнопки повтора нет. Поле Telegram имеет отдельный фон и рамку. Внутренняя прокрутка только программная: колесо и свайп продолжают прокручивать сайт. От 1100 px — три колонки, ниже — вертикальная компоновка. RU/EN, Tailwind + Motion, статичный диалог при prefers-reduced-motion; таймер приостанавливается вне экрана и в скрытой вкладке. Каналы и API не подключены.

- Адаптивный футер с контактами, RU/EN и SVG Instagram, X, LinkedIn. Почта и телефон кликабельны. Официальные адреса профилей задаются через frontend/.env.local по шаблону .env.example; до настройки иконки не являются ссылками. Реальные профили не выдумываются.

- Логотип пользователя и белая кнопка «Войти» с чёрной рамкой без ссылок FAQ и «Как работает».
- Хедер скрывается вниз по странице и возвращается при прокрутке вверх. У начала страницы всегда виден; мелкие движения игнорируются.
- Бургер на всех размерах экрана раскрывает полноэкранное чёрное меню с пунктами 26–28 px без нумерации по механике EFEM: панель сверху, последовательное появление пунктов и обратная анимация закрытия. Бургер превращается в крестик. Пока меню открыто, прокрутка страницы заблокирована; Escape закрывает меню, фокус клавиатуры удерживается внутри. Переход к секции выполняется после закрытия панели.
- Анимация Motion отключается при prefers-reduced-motion. Фокус клавиатуры возвращает скрытый хедер.
- Главная содержит hero, интерактивный сценарий, память клиента, этапы подключения, каналы, пример статистики, FAQ и форму пилота; тексты RU/EN.
- Демо использует готовые ответы и вымышленные объекты, не API модели. График статистики реализован локальным доступным HTML/CSS-компонентом, без зависимости Bklit; данные демонстрационные. Форма пилота открывает mailto с черновиком письма — серверное сохранение заявок пока не подключено.
- /login, /register, /forgot-password — формы входа, регистрации и восстановления по референсу: заголовок по центру, компактные округлые поля с иконками, переключение видимости пароля, встроенная валидация и чёрная основная кнопка. Неподключённая кнопка Google скрыта. Выбор языка раскрывается кнопкой с глобусом. Вход и самостоятельная регистрация подключены к backend через HttpOnly-сессию. После регистрации показано ожидание письма. `/verify-email` подтверждает одноразовую ссылку и открывает `/create/wizard` с HttpOnly-сессией. Сервер создаёт отдельный бизнес и пустой черновик; мастер автоматически сохраняет шаги и материалы, восстанавливает их при повторном входе и сообщает о конфликте вкладок. Гостевое демо можно явно перенести в пустой черновик аккаунта. Пароль при регистрации — 10–128 символов; ошибки и повторная почта показываются в форме. `/forgot-password` запрашивает письмо, `/reset-password` задаёт новый пароль с повторным вводом. Ссылки читаются из fragment и удаляются из адресной строки; GET не расходует токен. RU/EN, состояния отправки, ошибки, пауза повторной отправки. Google OAuth не подключён, кнопка скрыта. Настройка писем — [../docs/account-auth.md](../docs/account-auth.md).
- Переключение RU/EN в раскрывающемся меню и на страницах авторизации, выбор сохраняется локально. Все текущие тексты переведены. Код ky зарезервирован в src/lib/i18n.tsx, кыргызский пока не переводится; кнопка KY видна, но отключена до готовности перевода.

Бизнес-логика и ключи провайдеров находятся в backend. Браузер не подключается напрямую к PostgreSQL или API моделей.

Далее реализуем лендинг, демо на вымышленных данных и форму заявки. Функции телефонии показываем только в соответствии с их реальным статусом.

График статистики: Bklit UI (локальные компоненты в src/components/charts) и Visx. Зависимости устанавливаются обычным npm install. Периоды 7/30 дней и все показатели используют общий вымышленный набор данных; backend аналитики не подключён. Источник, лицензия и локальные изменения описаны в src/components/charts/README.md.

Проверки мастера (Node.js 22.18+): `node --test tests/create-agent.test.mjs`. Проверяют URL, лимиты материалов, ответы только из FAQ и передачу человеку.

Проверки кабинета: `node --test tests/*.test.mjs`. `dashboard-dialogues` — порядок и слияние страниц сообщений, ключ идемпотентности при повторе, лимиты Telegram (символы) и Instagram (байты), время в Бишкеке, тексты статусов; `dashboard-integrations` — «подключён» только по данным сервера, «требуется действие» без серверной конфигурации; `api-proxy` — белый список прокси, CSRF-проверка, разбор ошибок, backoff опроса.

Проверки мастера WhatsApp: `node --test tests/whatsapp-setup.test.mjs`. Проверяют переход из обычного WhatsApp, пропуск проверки приложения в облачной ветке и обязательный выбор оплаты.

Самостоятельный Telegram: клиент вводит токен в кабинете, секрет хранится зашифрованно, контрольная доставка проверяется перед включением агента. Docker запускает обработчик очереди вместе с API. В «Диалогах» показана готовность бизнеса, материалов, теста и канала. Нужна миграция 011. [Инструкция](../docs/telegram-self-service.md).
